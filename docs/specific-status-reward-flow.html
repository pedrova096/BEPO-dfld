Specific Status Reward Flow

Flow from starting a run, to preparing specific-status reward doors, to entering the next stage with a locked reward variant.

Reading The Diagrams

Runtime Pieces

Kind Meaning Examples
Controller / Manager A Defold script attached to a game object. It can receive msg.post messages through on_message. game_controller.script, level_manager.script, door_controller.script
Module A plain Lua module loaded with require. It is called directly like a normal object/function. modules.level.level, lib.rewards.specific_status_picker
Message A Defold msg.post(...) between scripts/game objects. It is handled later by on_message. Msg.Game.START_RUN, Msg.Stager.LOAD_STAGE
Invocation A direct Lua function call in the same frame. No Defold message is posted. self.level:start_run(...), on_load_level_stage(...)

Arrow Labels

[message]  Defold msg.post(...)
[call]     direct Lua function/module call
[internal] local function call or local state mutation
[factory]  Defold factory.create(...)

1. Run Start And First Stage Load

sequenceDiagram
  participant UI as UI Controller
  participant Game as Game Controller
  participant Level as Level Module
  participant Stage as Level Manager
  participant Door as Door Controller

  UI->>Game: [message] Msg.Game.START_RUN { level_id }

  Game->>Game: [internal] reset run-specific reward state
  Game->>Level: [call] start_run(level)
  Level-->>Game: stage_payload for stage_1

  Game->>Game: [internal] on_load_level_stage(stage_payload)
  Game->>Game: [internal] prepare reward variants on stage_payload

  Game->>Stage: [message] Msg.Stager.LOAD_STAGE { stage = stage_payload }

  Stage->>Stage: [internal] create tilemap
  Stage->>Stage: [internal] spawn_connections(stage.connections)
  Stage->>Door: [factory] create door with next_stage, reward, reward_variant

  Stage-->>Game: [message] Msg.Stager.STAGE_LOADED
  Game->>Level: [call] load_stage(stage_payload)
  Game->>Level: [call] start_stage()
  Game->>Stage: [message] Msg.Stager.START_STAGE

Reward variants are prepared before level_manager receives the stage payload. By the time doors are spawned, each specific-status door already has a concrete reward_variant.

2. Door Reward Variant Preparation

This is internal reward preparation inside the game flow. It is not a Defold message by itself.

flowchart TD
  A[Game has stage_payload] --> B{stage_payload has connections?}

  B -- No --> Z[No door rewards to prepare]
  B -- Yes --> C[Loop stage_payload.connections]

  C --> D{connection.reward == SpecificStatus?}

  D -- No --> E[Leave connection unchanged]
  D -- Yes --> F{connection.reward_variant exists?}

  F -- Yes --> G[Keep existing variant]
  F -- No --> H[Roll weighted status variant]

  H --> I[Set connection.reward_variant]
  G --> J[Door can display exact reward]
  I --> J
  E --> K[Normal door reward]

After preparation, a specific-status door connection looks like this:

{
  id = hash("stage_2"),
  reward = Rewards.SpecificStatus,
  reward_variant = Status.Life,
}

Then level_manager creates the door with:

{
  next_stage = connection.id,
  reward = connection.reward,
  reward_variant = connection.reward_variant,
}

3. Enter Door And Load Next Stage

sequenceDiagram
  participant Player
  participant Door as Door Controller
  participant Game as Game Controller
  participant Level as Level Module
  participant Stage as Level Manager

  Player->>Door: [physics] enters wall_trigger

  Door->>Game: [message] Msg.Stager.CONNECTION_ENTERED
  Note right of Door: payload: next_stage, reward, reward_variant

  Game->>Level: [call] choose_connection(next_stage)
  Level-->>Game: next stage_payload

  Game->>Game: [internal] record selected reward variant
  Game->>Game: [internal] stage_payload.reward_variant = selected reward_variant

  Game->>Game: [internal] on_load_level_stage(stage_payload, transition=true)
  Game->>Stage: [message] Msg.Stager.LOAD_STAGE { stage = stage_payload }

  Stage->>Stage: [internal] current_stage_reward = stage.data.reward
  Stage->>Stage: [internal] current_stage_reward_variant = stage.reward_variant

  Stage-->>Game: [message] Msg.Stager.STAGE_LOADED

The selected door variant is locked into the next stage:

stage_payload.reward_variant = message.reward_variant

If the player enters a Life door, the next stage carries:

stage_payload.reward_variant = Status.Life

When that stage is completed, the upgrader spawns with:

{
  reward = Rewards.SpecificStatus,
  reward_variant = Status.Life,
}

Short Version

START_RUN
  -> [message] UI tells game_controller to start
  -> [call] game_controller asks Level module for the first stage
  -> [internal] game_controller prepares reward variants
  -> [message] game_controller tells level_manager to load the stage
  -> [factory] level_manager creates doors

ENTER DOOR
  -> [message] door_controller sends selected next_stage/reward/reward_variant
  -> [call] game_controller asks Level module to resolve the next stage
  -> [internal] game_controller locks the selected reward_variant into that stage payload

NEXT STAGE
  -> [message] game_controller tells level_manager to load the next stage
  -> [internal] level_manager stores the locked reward_variant
  -> on completion, the upgrader uses that exact variant
